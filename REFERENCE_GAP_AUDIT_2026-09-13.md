# Эталон и новый сайт: помощь после опроса

Проверка 13.09.2026 в Codex Browser и по Django-коду. Эталон: https://карманныйюрист.рф/. Проверены публичная главная, каталог, тестовая ветка судебного приказа, формы всех трёх пакетов, вход и регистрация. Покупки, регистрация и отправка личных данных на эталоне не выполнялись. Закрытая выдача не проверена: нет оплаченного тестового аккаунта. Наличие рекламного обещания не считается подтверждением работающей функции.

## Что уже перенесено

Выбор темы → вопрос/ответ без промежуточных комментариев → краткий вывод с вероятностью и причиной из соответствующего Word → три пакета с точными названиями, составом и ценами 298 / 498 / 697 ₽.

Теперь «Получить помощь» открывает оформление конкретного пакета: ФИО, почта, телефон, состав и сумма. У нас форма отдельной страницей; у эталона это всплывающее окно. Реализовано сохранение неоплаченного заказа и «Мои заказы» для текущей сессии браузера. Цена и итог берутся сервером из завершённой ветки; состав и сумма фиксируются в заказе. Повторная отправка не создаёт дубль. Чужой заказ по ссылке не открывается. Это ещё не личный кабинет с входом с другого устройства.

У эталона форма говорит о регистрации кабинета и содержит «Оплатить». У нас эта часть намеренно не объявлена готовой: кнопка формы — «Сохранить заказ», оплата на заказе недоступна. Не создаются фиктивные оплаченные платежи, не выдаются платные тексты и не заявляется отправленное письмо.

## Порядок дальнейшего переноса

1. Получить доступ к уже купленному тестовому пакету или админке эталона и точные материалы всех трёх услуг. Проверить реальные экраны выдачи, скачивания и докупки, не угадывать закрытые алгоритмы.
2. Подключить выбранный платёжный сервис в тестовом режиме. Основание выдачи — подтверждённый сервером платёж, а не переход на success URL. Зафиксировать цены, состав, возвраты и повторные уведомления.
3. Добавить пользовательский кабинет, права на отдельные услуги, библиотеку покупок и доставку почтой. Сначала провести путь «оплата → только купленные услуги → повторный вход → скачивание» на одном опроснике.
4. Подключить планы/шаблоны и докупку. Затем импортировать остальные опросники тем же форматом, без копирования серверной логики для каждого из них.
5. Перед публичным запуском — постоянный тестовый сервер, оператор/правовые документы, проверка защищённой выдачи и замена старой демонстрационной оплаты.

## Существенные ограничения старого кода

`views.user_payment` для старых опросников безусловно устанавливает `paid` и сообщает об отправке письма без настоящей оплаты. `payment_success` получает платёж по ID без проверки владельца. Для импортированных опросников этот путь заблокирован; новый HelpOrder его не использует. Старый путь нельзя включать в публичный платёжный сценарий без исправления. В кодовой базе также ранее найдено отсутствие миграции для UserDocumentData; новая миграция 0010 создаёт только HelpOrder и не исправляет несвязанный старый генератор.

## Проверки текущего изменения

28 Django-тестов: 32 ветки, все пакеты, вход только после результата, валидация данных, CSRF, чужая сессия, подмена суммы/вывода, повторная отправка, устаревшая форма и изменение тарифа. Тестовые базы отдельные; исходная db.sqlite3 не изменялась. В локальном RAM-preview заказы пропадают при перезапуске, в обычной БД модель сохраняется после миграции. Реальный платёж, письмо и выдача пока не проверены и не реализованы.
