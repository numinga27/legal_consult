# Подключение ЮKassa

Магазин k-urist.ru, shopId 1502543. Секрет хранится только в `/home/numinga/.config/legal-consult/app.env` (numinga, 600), не в Git и не в логах.

## Настройки сервера

- `PAYMENT_PROVIDER=yookassa`
- `YOOKASSA_SHOP_ID=1502543`
- `YOOKASSA_SECRET_KEY`: ключ владельца магазина
- `YOOKASSA_ENABLED=0` до проверки магазина и чеков; `1` после настройки
- `YOOKASSA_TEST=0` для боевого магазина, `1` только для тестового. Ответ API обязан совпадать с этим режимом.
- Для чеков через ЮKassa: `YOOKASSA_RECEIPTS=1`, `YOOKASSA_VAT_CODE` по подтверждённым данным продавца. Код НДС не определяется по названию компании. Если у кассы несколько систем налогообложения, передавать согласованный `tax_system_code` через `YOOKASSA_TAX_SYSTEM_CODE`.
- Если продавец формирует чеки вне API ЮKassa: только после подтверждения способа установить `YOOKASSA_RECEIPTS_EXTERNAL=1`. Этот флаг означает подтверждённую внешнюю фискализацию; отсутствие настроек кассы не разрешает включать его автоматически.

`deploy/configure-yookassa.py` запускается на сервере от numinga. Получает JSON `shop_id`, `secret_key` через stdin, сверяет магазин запросом GET /me и атомарно сохраняет ключ с выключенной оплатой. Скрипт не выводит ключ. Не передавать секрет аргументом команды или через shell history. После настройки перезапустить `sudo supervisorctl restart legal_consult`.

## Уведомления в кабинете клиента

Интеграция → HTTP-уведомления:

- URL: `https://www.k-urist.ru/payments/yookassa/callback/`
- События: `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`.

Настройка уведомлений по API доступна для OAuth-интеграций. Для обычного shopId и секретного ключа настройка выполняется в кабинете. При отсутствии доступа к кабинету это действие выполняет владелец. Возвращение на сайт и кнопка проверки дополнительно запрашивают актуальный статус через API.

## Проверка перед включением

1. GET /me: правильный account_id, активный магазин, ожидаемый test, способ отправки чеков подтверждён. Секрет или полный ответ не журналировать.
2. Автоматические тесты: серверная сумма, защищённая выдача, отмены, повторы, возвраты и невозможность подделать подтверждение.
3. Контрольный платёж с согласованной суммой выполняет владелец. Наличие API-ключа не разрешает агенту списывать деньги. Проверить webhook, возврат на сайт и доступ из аккаунта покупателя.

Тесты используют имитацию API и не подтверждают реальный эквайринг. Не заявлять включение при отсутствии фактического readback сервера.

## Поведение

Каждая услуга оплачивается своим заказом. Сумма и подготовленные материалы проверяются на сервере. Без материалов оплатить нельзя. Платёж подтверждается только GET-запросом к API с проверкой магазина, режима test, суммы, валюты и привязки заказа. Запрос из браузера или статус в webhook не открывает доступ самостоятельно.

При сетевой ошибке сохраняется попытка и полный исходный запрос. Повтор использует тот же Idempotence-Key и payload только в течение 23 часов (гарантия ЮKassa: 24 часа); позднее требуется ручная сверка. Отменённый платёж разрешает новую попытку. Активные попытки другого провайдера блокируют новый счёт. Полный возврат закрывает доступ, частичный сохраняет его. Функция возврата денег из админки не добавлялась: возвраты выполняются в кабинете ЮKassa.
